## Done recently (rolling)

- [x] 2026-08-06 — **One-Stop Phase 8: the capstone.** `linkd` at `labs/capstone` and `/capstone`: a link shortener with API-key auth, per-token rate limiting, durable storage and metrics, specified in SPEC.md and graded by a 34-check black-box suite plus four SLOs, with **zero guidance** (no steps, no starter functions, no suggested layout). Nothing in the harness reads the submission's source: it compiles the package, runs the binary, and speaks HTTP, which keeps "any layout that meets the spec passes" literally true and forced every requirement to be one that can be observed from outside. Two draft requirements were cut during the build because they could not be. **The deliverable is the seeded-bug harness, not the suite**: `go run ./seed` copies the reference, applies one named bug, compiles it, and runs exactly the checks that bug should trip. 11 seeds, all caught, 9 of them straight from the Phase 5 failure classes. It keeps `stale` (the patched code moved), `broken` (it does not compile) and `missed` (the bug went in and the suite passed) apart, because only the last is a hole in the suite — and that earned its keep the same session, when refactoring the store moved the `data-race` seed's anchor and the prover said `stale` rather than quietly passing. **A lost update turns out not to be observable from outside a service**, and the first seed proved it: removing the lock from click counting and firing 250 concurrent redirects passed consistently, because 250 increments spread across milliseconds of HTTP overhead never collide in a two-nanosecond window. The seed that works removes the lock from the write path, where map iteration for a snapshot is wide open long enough for the runtime to catch it and kill the process (verified 6/6). A near-miss variant that fires ~50% of the time was deliberately excluded, since an intermittent seed is worse than none. That finding is now taught on the page rather than hidden, and the six failure classes with no seed each ship the reason they have none — validate.ts enforces that all 15 appear in exactly one of the two lists and none in both. **The SLO harness caught an O(n²) write path in my own reference**, which is the best evidence it works: p99 came in at 209ms against a 50ms bar, not from fsync (removing it only reached 124ms) but from rewriting the whole store on every create under the save lock. Group commit fixed it — one disk write satisfies every caller whose mutation predates its snapshot — taking p99 to **16.0ms** and throughput from 10,891 to **24,174 req/s** with fsync kept; thresholds were then set from that measurement, and the pre-fix version fails them. **Measured the instrument too**: a p50 of `0s` next to a 4.5ms mean was impossible, and a direct probe found this machine's monotonic clock ticks every ~525µs (199,998 of 200,000 back-to-back `time.Now()` calls identical), so the harness now measures and prints that granularity and says which percentile carries weight. Two checks were caught passing for the wrong reason — `startup/requires-tokens` and `startup/refuses-corrupt-store` both passed against a binary that only ever exits 1 — and now run a positive control first. The Windows-only skip (`shutdown/drains-and-exits-zero` needs a signal the platform cannot deliver to a child) announces itself on its own line. Drive-by: `npm run lint` was red on generated code inside a stale worktree under `.claude/`, since the inherited ignores only cover root-level build output; fixed in `eslint.config.mjs`. Build green at 123 pages (was 122); tsc, validate, lint, `labs/capstone/check.sh` and the full `labs/check.sh` all green.

- [x] 2026-07-25 — **One-Stop Phase 7: guided source reading.** The five walkthroughs the brief names, live at `/source`: the `errors` package, `bytes.Buffer`, `sync.WaitGroup`, `context`, and the `net/http` Server accept loop. 30 annotated excerpts, one find-it exercise each behind a reveal, plus a `SourceWalkthrough` type, a validate.ts contract, and reverse links onto 24 concept pages and 8 project pages so the brief's done-when ("reachable from the relevant concepts and projects") is structural rather than aspirational. **The design problem here was rot, not pedagogy**: every other track verifies code we wrote, this one quotes code we do not control from files that change every release, and a drifted quote teaches the reader that the site is unreliable exactly when it asks them to trust source over docs.
